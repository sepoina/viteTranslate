### S1. `lib/dev/vite/uty/syncError.js` (new)

```js
export class SyncError extends Error {
  constructor(code, message, { filePath, paths, written, cause } = {}) {
    super(message, cause === undefined ? undefined : { cause });
    this.name = "SyncError";
    this.code = code;
    if (filePath !== undefined) this.filePath = filePath;
    if (paths !== undefined) this.paths = paths;
    if (written !== undefined) this.written = written;
  }
}
```

The only codes introduced by this release:

| Code | Thrown by | Extra fields | The message must say |
| --- | --- | --- | --- |
| `VT_SCAN_INCOMPLETE` | `runSync` | `paths`: the `skipped` strings | how many files, each `path: reason`, "no language table was touched", "fix the file(s) and run again" |
| `VT_LANGUAGE_UNREADABLE` | `updateLanguage` (phase P1) | `paths` | every unreadable file with its reason, "no language table was touched" |
| `VT_BACKUP_FAILED` | `backupLanguageFile` | `filePath`, `cause` | which file, why, "nothing was overwritten" |
| `VT_FILE_CHANGED` | `replaceFileAtomic` | `filePath` | the file changed after it was read; "run again once the other edit is done" |
| `VT_WRITE_FAILED` | `replaceFileAtomic` | `filePath`, `cause` | which file failed and why |

In the commit phase `updateLanguage` re-throws `VT_FILE_CHANGED` / `VT_WRITE_FAILED` as a new `SyncError` with the same code and `filePath`, `cause` = the original error, `written` = the files this run had already replaced, and a message that names them ("partial update: run the sync again").

Messages: English, one readable paragraph, no stack. Each failure is printed **once**, at the boundary: `cli.js` `main().catch`, `autoSync` G14, or the LLM CLI. Low-level code throws; it does not log the failure.

### S2. Snapshot — new field `snapshot` in the result of `readLanguageForSync`

```js
{ kind: "absent" }                                                // lstat said ENOENT
{ kind: "file", bytes: Buffer, realPath: string, mode: number }  // exactly what was read
null                                                              // only for status "unreadable"
```

- `bytes`: the Buffer of the single `readFileSync(filePath)` call (no encoding). The text used for parsing is `bytes.toString("utf8")`, which decodes exactly like today's `readFileSync(path, "utf8")`.
- `realPath`: `realpathSync(filePath)`. `mode`: `statSync(filePath).mode & 0o7777`.
- Status → snapshot: `missing` → absent; `corrupted`, `empty`, `ok` → file (a zero-byte file is `kind: "file"` with an empty Buffer); `unreadable` → `null`.
- `oldText` keeps its exact current meaning: the text only when `status === "ok"`, `null` otherwise. Never derive it from `snapshot`.
- Dangling symlink: today `existsSync` is false, so it is `missing`. New: if `lstatSync` succeeds but the target does not exist, the status is `unreadable` (the intent already written in `readLanguageFile.js`: "un link rotto"). All other classifications are unchanged.

Add `export function readLanguageBytes(filePath)` to `readLanguageFile.js`, with the same error shape as `readLanguageText` (`unreadable: true`, `cause`). `readLanguageText` becomes `readLanguageBytes(filePath).toString("utf8")`.

### S4. `lib/dev/vite/uty/replaceFileAtomic.js` (new)

`export default function replaceFileAtomic(filePath, text, expected)`: synchronous, throws `SyncError`.

Steps, in this order:

1. `target = expected.kind === "file" ? expected.realPath : filePath` (a symlink is followed: the link stays, its target is replaced).
2. Temporary name in `dirname(target)`: `.${basename(target)}.vt-tmp-${process.pid}-${randomHex(8)}` (`Math.random`, zero-padded: uniqueness comes from `wx`, not from the random part). The leading dot and the missing `.yml` ending keep it out of `isLanguageFileName`, the compile-locale filter and the dev watcher.
3. `fd = syncIo.openSync(tmp, "wx", 0o666)`; on `EEXIST` draw a new name (at most 5 attempts). Write `Buffer.from(text, "utf8")` in a loop until every byte is written (`writeSync` may write less). `closeSync` in `finally`.
4. If `expected.kind === "file"`: `syncIo.chmodSync(tmp, expected.mode)` (the `openSync` mode is masked by umask). When `syncIo.platform === "win32"`, ignore chmod errors.
5. Conflict check, right before **every** rename attempt (including after each retry wait):
   - `absent`: if `syncIo.lstatSync(filePath)` succeeds → `VT_FILE_CHANGED`.
   - `file`: `syncIo.realpathSync(filePath) !== expected.realPath` → `VT_FILE_CHANGED`; `syncIo.readFileSync(target)` failing with `ENOENT`, or returning bytes where `!current.equals(expected.bytes)` → `VT_FILE_CHANGED`.
6. `syncIo.renameSync(tmp, target)`. Only when `syncIo.platform === "win32"`: retry on `EPERM` / `EBUSY` / `EACCES` up to 4 more times, waiting 25, 50, 100, 200 ms with `Atomics.wait(new Int32Array(new SharedArrayBuffer(4)), 0, 0, ms)`. Editors and antivirus software hold files open on Windows; without this retry the sync would fail where `writeFileSync` used to work.
7. Any failure in steps 3–6: `syncIo.unlinkSync(tmp)` in its own `try` (ignore its errors), then throw. A `SyncError` passes through unchanged; anything else becomes `VT_WRITE_FAILED` with `filePath` and `cause`.

Never truncate, delete or rewrite `filePath` / `target` in any other way. No fsync, no lock, no async, no new dependency.

Limits to document: atomic per file only; no multi-file transaction; no power-loss guarantee; the check is optimistic, so a race window remains between steps 5 and 6; no cross-process lock; rename breaks hard links and does not keep the owner (uid/gid) of a file owned by another user.

2. Date only: `const date = utcCalendarDate(+m[1], +m[2], +m[3]); return date ? { date, dateOnly: true } : null;`. Date-only output stays in UTC, independent of the user's time zone.
3. ISO date-time: before `Date.parse`, validate its first 10 characters with `utcCalendarDate` (`ISO_RE` guarantees `YYYY-MM-DD`); invalid → `null`. Do not change `ISO_RE` or the time-zone interpretation.
4. Fallback unchanged: primitives are returned as they are, an invalid `Date` becomes `String(v)`. No blanket `try/catch` around formatting. Formatter caches unchanged.
5. `0000-01-01` is year 0 (formatted as Intl does), never 1900.
