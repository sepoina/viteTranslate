## Il concetto (leggilo prima di scrivere codice)

### Il percorso di un testo

```text
testo nel .yml ─► ICU_TRIGGER_RE ("{0" / "{nome}")? ── no ──► percorso 4.6.2
                        │ sì
                        ▼
   normalizePlaceholders: il k-esimo %s → {k}  (fuori dalle citazioni '…')
                        ▼
   parse formatjs (ignoreTag: true) + controlli nostri:
   nomi degli argomenti, apostrofo prima di "{", stili, opzioni validate con Intl
        │ problema → avviso nel reporter + percorso 4.6.2 (testo semplice)
        ▼
   AST → modello di testo con "slot" n al posto di ogni argomento
        → parseMarkup (il markup di sempre) → espressione JS
        ▼
   voce compilata: (a, o) => _cat([...]) | jsx(...), che chiama
   _icuN / _icuD / _icuP / _icuS importati da "virtual:vitetranslate/icu"
```

**Perché gli slot.** Il markup (`<b>`) e l'ICU si annidano in entrambe le direzioni: un `<b>` può contenere un plurale, e un ramo
plurale può contenere `<b>#</b>`. formatjs con `ignoreTag: true` lascia i tag dentro i letterali. Si ricompone quindi ogni
messaggio (quello principale e ciascun ramo) come **stringa modello**, in cui ogni elemento ICU è sostituito da un token
privato `<indice>`. Su quella stringa gira il `parseMarkup` di sempre, e nei nodi di testo i token tornano a
essere espressioni JS: è lo stesso meccanismo con cui oggi si spezza `%s`. Un tag aperto fuori da un ramo e chiuso dentro
non si ricompone: `parseMarkup` è tollerante, lo chiude da solo. È un limite documentato.

### La forma compilata, su un esempio

Sorgente it-IT: `Hai {0, plural, =0 {nessun file} one {<b>#</b> file} other {# file}}`

```js
import { icuPlural as _icuP } from "virtual:vitetranslate/icu";
// ... _arg / _cat inline come oggi ...
"App_x": (a, o) => _cat(["Hai ", _icuP(_arg(a, 0), "it-IT", 0, 0,
  { "0": (h0) => "nessun file" },
  { "one": (h0) => jsxs(Fragment, { children: [jsx("b", { children: h0 }), " file"] }),
    "other": (h0) => _cat([h0, " file"]) })])
```

- `a` sono gli argomenti di sempre: array, scalare o, da ora, oggetto. `{n}` si legge con `_arg(a, n)`, `{nome}` con
  `_key(a, "nome")`. `o` sono le **opzioni di runtime** (per ora solo `{ timeZone }`), passate da `resolveEntry`.
- `h0` è il numero già formattato che prende il posto di `#`. Un plurale annidato usa `h1`, e così via: ogni `#` si riferisce
  al plurale più interno che lo contiene.
- Le opzioni `Intl` si hoistano come costanti del modulo (`const _o0 = {...};`): la cache le riconosce per identità.

### Dove si controlla, e cosa succede

| Dove | Problema nel sorgente | Traduzione con argomenti diversi o ICU rotto | Categorie plurali mancanti |
| :- | :- | :- | :- |
| Compilazione (plugin) | avviso + testo semplice | avviso + voce della **sorgente** + `🔸` (in `__untranslated__`) | avviso, la voce si compila (ripiega su `other`) |
| `--status` | nota `warning` sulla riga sorgente | nota `warning` sulla riga della lingua | nota `warning` |
| `--llm-translate` | — | rifiuto → resta `null`, un giro di riparazione | rifiuto |
| Runtime dev, chiave non sincronizzata | l'interprete rinuncia, si vede il fallback di sempre | — | — |

### Argomenti: per posizione o per nome

| Scritto | Passato | Si legge |
| :- | :- | :- |
| `{0}`, `%s` | `a={[x, y]}`, `t={[testo, x, y]}`, `ts(t, [x, y])` | `a[0]` |
| `{0}`, `%s` | `a="x"` (scalare) | `"x"` per `{0}`, assente per gli altri |
| `{nome}` | `a={{ nome: "Aldo" }}`, `ts(t, { nome })` | `a.nome` |
| `{nome}` e `{1}` | `a={[{ nome }, 3]}`, `t={[testo, { nome }, 3]}` | `a[0].nome` e `a[1]` |
| `{0}`, `%s` | `a={{ nome }}` | `a["0"]`: quasi sempre assente → `⁇` |

Regole comuni ai due helper, e al runtime (`lib/namedArgs.js`):

- un campo o un indice assente, `null` o `undefined` → `⁇` (`mark.absentDataInArray`), come oggi;
- un **oggetto semplice** come valore non si rende mai → `⁇`. Oggi fa lanciare React;
- `0`, `""` e gli elementi React restano valori veri;
- la lettura per nome usa `Object.hasOwn`, quindi `{constructor}` non pesca dal prototipo.

### Glossario del piano

- **messaggio ICU**: un testo che soddisfa `ICU_TRIGGER_RE`.
- **chiave** di un argomento: il testo fra le graffe prima della virgola, cioè `"0"`, `"1"` oppure `"nome"`.
- **oggetto semplice** (`isNamedArgs`): non `null`, `typeof "object"`, non un array, senza `$$typeof` (quindi non un elemento React), con prototipo
  `Object.prototype` oppure `null`.
- **firma** (signature) di un testo: le chiavi degli argomenti con la loro **famiglia** (`any` per `{n}`, `{nome}` e `%s`,
  `number` per number/plural/selectordinal, `date` per date/time, `select`), più le chiavi dei rami di plurali e select.
  Due firme sono compatibili se hanno le stesse chiavi e nessuna chiave è `number` in una e `date` nell'altra.
- **slot**: il token `n` del modello di testo.

## Proposta: timestamp e fuso orario (dentro la 4.6.3)

Tre problemi reali, ciascuno con la sua regola.

**1. Che cosa è una data.** `{n, date}` e `{n, time}` accettano:

| Valore | Significato | Fuso usato |
| :- | :- | :- |
| `Date` valida | un istante | quello risolto al punto 2 |
| numero finito | un istante in **millisecondi** (convenzione JS) | punto 2 |
| `"YYYY-MM-DD"` | una **data di calendario**, non un istante | **sempre UTC**, così `"2026-10-03"` non diventa il 2 ottobre a New York |
| `"YYYY-MM-DDTHH:mm[:ss[.fff]][Z\|±HH:mm]"` | un istante ISO 8601 (senza offset: ora locale, come da specifica JS) | punto 2 |
| qualunque altro valore | non si interpreta: niente `Date.parse` euristico, che cambia da motore a motore | — si mostra com'è (`Date` non valida → `String(v)`) |

**Secondi al posto di millisecondi.** È il bug classico delle API che restituiscono timestamp Unix. In sviluppo, un numero diverso
da 0 con `|v| < 1e11` (cioè prima del 3 marzo 1973, se letto in millisecondi) produce **una volta** un `console.warn` che
suggerisce di moltiplicare per 1000. In produzione il ramo non esiste (`import.meta.env.DEV`).

**2. Quale fuso orario**, in ordine di precedenza:

1. data di calendario (`"YYYY-MM-DD"`) → `UTC`, sempre;
2. prop `timeZone` di `<TranslateContainer>` (a runtime: la preferenza dell'utente, o il fuso della richiesta in SSR);
3. opzione del plugin `icu: { timeZone: "Europe/Rome" }` (default di build, per esempio gli orari di un ristorante che vanno
   mostrati nel fuso del ristorante);
4. niente: il fuso del runtime (quello del browser; in SSR quello del server).

**3. SSR e idratazione.** Con il punto 4, server e browser formattano in fusi diversi e React segnala un mismatch di
idratazione. La documentazione lo dice in chiaro: chi fa SSR con date imposta il punto 2 o il punto 3.

**Il meccanismo.** Il fuso non entra nel codice compilato: la stessa build vale per qualunque fuso. Viaggia a runtime come
`o = { timeZone }`: `TranslateContainer` lo mette nel context (`lang.icu`), il manifest esporta il default del plugin
(`export const icu`), e i punti di chiamata passano `lang?.icu ?? manifest.icu` a `resolveEntry`, che lo passa alla voce
compilata. La cache `Intl` include il fuso nella chiave.

**Alternative scartate.** Un `setTimeZone()` globale: stato di modulo condiviso fra le richieste SSR concorrenti.
Il fuso cotto nelle opzioni a compile time: l'output dipenderebbe dalla config, e l'interprete di dev dovrebbe riceverlo per
un'altra strada. Un fuso per singolo valore (`{ date, timeZone }`): utile, ma resta fuori dalla 4.6.3 (§ "Fuori perimetro").

### 1.2 `lib/markerSyntax.js` — l'innesco

In coda al blocco "Segnaposto degli argomenti":

```js
// --- Messaggi ICU (4.6.3) ---
//
// Un testo è un messaggio ICU MessageFormat solo se contiene un argomento ICU: "{" + cifra
// ("{0", "{ 1 ,"), oppure "{" + nome chiuso subito ("{nome}") o seguito da una virgola e da un
// tipo ICU ("{n, plural,"). Una graffa qualunque non basta, e non è prudenza teorica: le tabelle
// di playEdge contengono già "{ t: null }", "{ t, a }" e "${}", che devono restare testo.
// Tre lettori: il compilatore delle tabelle, il validatore LLM e l'interprete di dev.
export const ICU_TRIGGER_RE =
  /\{\s*\d|\{\s*[\p{L}_][\p{L}\p{N}_]*\s*(?:\}|,\s*(?:number|date|time|plural|selectordinal|select)\s*[,}])/u;

// Il nome di un argomento: numerato ("0") oppure un identificatore ("nome", "città").
export const ICU_NAME_RE = /^(?:\d+|[\p{L}_][\p{L}\p{N}_]*)$/u;
```

(Nessuna delle due ha il flag `g`, quindi `.test()` non porta stato fra una chiamata e l'altra. La regex è verificata sul
repo: 0 corrispondenze nelle 2 686 righe di tabella; `{ t: null }`, `{ t, a }` e `${}` → no; `{name}`, `{ name }`, `{0}`,
`{count, number}`, `{n, plural, …}` e `{città}` → sì. Anche `Press {Enter}` → sì: diventa un argomento, e senza valore mostra `⁇`.
Va nella documentazione.)

### 1.3 `lib/icu/parse.js` — innesco, normalizzazione, parse, controlli

File puro: niente Node, niente React. Lo usano il CLI, il plugin e, in dev, il browser. Importa solo
`../dist/icuParser.js` e `../markerSyntax.js` (`ICU_TRIGGER_RE`, `ICU_NAME_RE`).

**Esporta:** `TYPE` (riesportato), `SLOT_OPEN = ""`, `SLOT_CLOSE = ""`, `isIcuCandidate`, `normalizePlaceholders`,
`parseIcu` e `forEachIcuNode`.

**Tipi dei nodi formatjs** (`TYPE`): `literal 0`, `argument 1`, `number 2`, `date 3`, `time 4`, `select 5`, `plural 6`, `pound 7`
(`tag 8` non compare mai, con `ignoreTag: true`). Il plurale ha `pluralType: "cardinal" | "ordinal"` e `offset`;
`select` e `plural` hanno `options: { [chiave]: { value: Nodo[] } }`; ogni nodo ha `location.start.offset` (con `captureLocation: true`).

**`isIcuCandidate(text)`**: `typeof text === "string" && ICU_TRIGGER_RE.test(text)`.

**`normalizePlaceholders(text)`** → `{ text, count, inBranch, offsets }`. Esattamente questo scanner, che rispetta le
citazioni di MF1 (`''` è un apostrofo letterale; `'` seguito da `{ } # |` apre una citazione, che si chiude al `'` successivo):

```js
export function normalizePlaceholders(text) {
  let out = "";
  let count = 0;
  let depth = 0;
  let inQuote = false;
  let inBranch = false;
  const offsets = [];
  for (let i = 0; i < text.length; i++) {
    const c = text[i];
    const next = text[i + 1];
    if (c === "'") {
      if (next === "'") { out += "''"; i++; continue; }
      if (inQuote) { inQuote = false; out += c; continue; }
      if (next === "{" || next === "}" || next === "#" || next === "|") { inQuote = true; out += c; continue; }
      out += c;
      continue;
    }
    if (!inQuote) {
      if (c === "{") depth++;
      else if (c === "}") depth = Math.max(0, depth - 1);
      else if (c === "%" && next === "s") {
        if (depth > 0) inBranch = true;
        offsets.push(out.length);
        out += `{${count++}}`;
        i++;
        continue;
      }
    }
    out += c;
  }
  return { text: out, count, inBranch, offsets };
}
```

**`parseIcu(text, tag)`** → uno di tre esiti:

- `{ icu: false }` se `!isIcuCandidate(text)`;
- `{ icu: true, ok: false, code, message }` per un problema bloccante;
- `{ icu: true, ok: true, ast, normalized, pctCount, warnings }`, dove `warnings` è `[{ code, message }]`.

I passi, in quest'ordine, e al primo problema bloccante ci si ferma:

1. se il testo contiene `SLOT_OPEN` o `SLOT_CLOSE` → `icu-reserved-char`: `the text contains U+E000/U+E001, reserved by viteTranslate's ICU compiler`;
2. se `/\p{L}'\{/u.test(text)` → `icu-apostrophe`: `an apostrophe right before "{" starts an ICU quote and hides the argument: write ’ (U+2019) or two apostrophes ''`;
3. `const norm = normalizePlaceholders(text)`. Se `norm.inBranch` → `icu-placeholder-in-branch`:
   `"%s" inside an ICU argument or branch: write the argument as {n} there`;
4. `parse(norm.text, { ignoreTag: true, requiresOtherClause: true, shouldParseSkeletons: true, captureLocation: true, locale })`,
   dove `locale` è `new Intl.Locale(tag)` in un try, e `undefined` se `tag` è vuoto o non valido. Un'eccezione → `icu-syntax`:
   `` `invalid ICU syntax (${e.message}${e.location ? ` at column ${e.location.start.column}` : ""})` ``. La colonna si riferisce
   al testo **normalizzato**: va bene così;
5. visita tutto l'AST con `forEachIcuNode`. Per ogni nodo di tipo 1–6:
   - `node.value` deve soddisfare `ICU_NAME_RE`, altrimenti `icu-argument-name`:
     `` `argument {${node.value}}: a name is letters, digits and "_", not starting with a digit — or a plain number` ``
     (formatjs accetta nomi più larghi, per esempio con il trattino; noi no, perché il nome è un campo JS scritto nel codice);
   - `number`: le opzioni si ricavano da `node.style`:
     - `null` → `undefined`;
     - `"integer"` → `{ maximumFractionDigits: 0 }`;
     - `"percent"` → `{ style: "percent" }`;
     - `"currency"` → `icu-style`: `` `{${i}, number, currency} needs a currency code: write {${i}, number, ::currency/EUR}` ``;
     - un'altra stringa → `icu-style`: `` `{${i}, number, ${s}}: unknown style, use integer, percent or a :: skeleton` ``;
     - un oggetto (skeleton) → `node.style.parsedOptions`;
   - `date`: `null` → `{ dateStyle: "medium" }`; `short|medium|long|full` → `{ dateStyle: s }`; un'altra stringa → `icu-style`
     (`unknown style, use short, medium, long, full or a :: skeleton`); uno skeleton → `parsedOptions`;
   - `time`: come `date`, con `timeStyle`;

```js

const ORDINAL = { type: "ordinal" };

const cache = new WeakMap();

const warned = new Set();

  if (warned.has(key)) return;
  warned.add(key);
  console.warn(`[vitetranslate] ${message}`);

function intl(Ctor, locale, options, timeZone) {
  const opts = options ?? EMPTY;
  let byKey = cache.get(opts);
  if (byKey === undefined) { byKey = new Map(); cache.set(opts, byKey); }
  const key = `${Ctor.name}\u0000${locale ?? ""}\u0000${timeZone ?? ""}`;
  let f = byKey.get(key);
  if (f === undefined) {
    f = build(Ctor, locale, opts, timeZone);
    byKey.set(key, f);
  }
  return f;

// con meno, e in sviluppo lo si dice una volta.
function build(Ctor, locale, opts, timeZone) {
  const tries = [
    [locale, timeZone === undefined ? opts : { ...opts, timeZone }],
    [locale, opts], [locale, EMPTY], [undefined, EMPTY],
  ];
  for (let i = 0; i < tries.length; i++) {
    try {
      const f = new Ctor(tries[i][0], tries[i][1]);
      if (i > 0 && import.meta.env?.DEV) warnOnce(`intl:${Ctor.name}:${locale}:${timeZone}`, `${Ctor.name} rejected locale "${locale}" with ${JSON.stringify(tries[0][1])}: formatted with fewer options.`);
      return f;
    } catch { /* tentativo successivo */ }
  }
  return new Ctor();
```

### 1.6 `lib/dev/compile/icu/icuSignature.js` — firma e confronto

Importa `parseIcu`, `isIcuCandidate`, `normalizePlaceholders`, `forEachIcuNode` e `TYPE` da `../../../icu/parse.js`, e
`PLACEHOLDER` da `../../../markerSyntax.js`.

- `signatureOf(text, tag)`:
  - con `text` non stringa → `{ ok: true, icu: false, args: new Map(), plurals: [], selects: [] }`;
  - `p = parseIcu(text, tag)`. Se `!p.icu`: `n = text.split(PLACEHOLDER).length - 1`, `args` = le chiavi `"0".."n-1"` con famiglia `any`;
  - se `!p.ok` → `{ ok: false, icu: true, code: p.code, message: p.message }`;
  - altrimenti visita l'AST: `args: Map<chiave (stringa), Set<famiglia>>`, `plurals: [{ key, ordinal, keys }]`, `selects: [{ key, keys }]`, e riporta `warnings: p.warnings`.
    La chiave è `node.value` così com'è (`"0"`, `"nome"`). Famiglie: argument → `any`, number e plural → `number`, date e time → `date`, select → `select`.
- `requiredPluralCategories(tag, ordinal)`: una cache `Map` su `${tag}|${ordinal}`. `new Intl.PluralRules(tag, { type })`,
  `select(n)` per `n` da 0 a 1000, più `"other"`, ordinato come in CLDR (`zero, one, two, few, many, other`). Un tag non valido → `["other"]`.
- `compareIcu(sourceText, translationText, targetTag)` → `{ errors: [], warnings: [] }` (ogni elemento `{ code, message }`):
  1. se nessuno dei due testi è ICU (`isIcuCandidate`), restituisci subito un risultato vuoto: **nessun parse**, così il percorso
     4.6.2 non paga niente;
  2. `s = signatureOf(sourceText)` (senza tag: dal sorgente servono solo gli argomenti). Se `!s.ok` → risultato vuoto:
     la sorgente rotta la segnala la sua lingua, e la traduzione si compila per conto proprio;
  3. `t = signatureOf(translationText, targetTag)`. Se `!t.ok` → `errors: [{ code: t.code, message: t.message }]`;
  4. chiavi: `missing = s − t` e `unexpected = t − s`. Se almeno uno non è vuoto → errore `icu-args`,
     `` `arguments differ from the source: missing {1}, {name}; unexpected {nome}` `` (ometti la parte vuota). È così che si
     scopre un nome tradotto (`{name}` → `{nome}`);
  5. per ogni chiave comune: se una delle due firme ha `number` e l'altra `date` → errore `icu-arg-type`,
     `` `argument {${k}} is a number in one text and a date in the other` ``;
  6. se `targetTag` c'è: per ogni plurale `p` della traduzione, `requiredPluralCategories(targetTag, p.ordinal) − p.keys`
     (ignora le chiavi `=n`) → avviso
     `icu-plural-categories`, `` `plural {${k}} lacks the ${targetTag} categories: few, many` ``;
  7. per ogni select del sorgente, le chiavi dei suoi rami meno l'unione delle chiavi dei rami dei select sullo stesso argomento nella traduzione → avviso `icu-select-keys`,
     `` `select {${k}} lacks the source keys: …` ``.
- `llmSourceText(text)`: restituisce `text` invariato se non è una stringa, se non è ICU o se non contiene `%s`; altrimenti
  `normalizePlaceholders(text).text`.

### 1.7 `lib/dev/compile/icu/compileIcu.js` — dall'AST all'espressione

Importa `parseMarkup` da `../parseMarkup.js`, `ARG`, `nodesExpr` e `pushTextParts` da `../emitTree.js`, `TYPE`, `SLOT_OPEN` e `SLOT_CLOSE` da `../../../icu/parse.js`.

```js
/**
 * @param {object[]} ast - un AST già validato da parseIcu (ok: true): qui non si fallisce più
 * @param {{ locale?: string, used: object, warn?: Function }} ctx
 * @returns {string} un'espressione JS
 */
export function compileIcuEntry(ast, { locale, used, warn }) {
  const st = { L: locale ? JSON.stringify(locale) : "void 0", used, warn };
  const { expr, dynamic } = messageExpr(ast, st, null, 0);
  return dynamic ? `(a, o) => ${expr}` : expr;
}
```

- `messageExpr(ast, st, pound, depth)`:
  - costruisce `template` e `slots`. Un letterale va aggiunto così com'è. Un `pound` diventa `slot(pound)`, oppure `"#"` se
    `pound === null`. Ogni altro nodo diventa `slot(elementIcu(node, st, depth))`, dove
    `slot(e)` fa `slots.push(e)` e restituisce `` `${SLOT_OPEN}${slots.length - 1}${SLOT_CLOSE}` ``;
  - `nodes = parseMarkup(template, st.warn)`;
  - testo senza markup (`nodes` vuoto, oppure un solo nodo `text`):
    - senza slot → `JSON.stringify(testo)`;
    - con slot → `parts` da `pushTextParts(testo, { n: 0 }, parts, slots)`. Se c'è **una sola parte ed è uno slot**, l'espressione è quella parte;
      altrimenti è `` `_cat([${parts.join(", ")}])` `` e si accendono `used.cat`, `used.jsxs` e `used.fragment`;
  - con markup → `nodesExpr(nodes, { n: 0 }, used, slots)`;
  - restituisce `{ expr, dynamic: slots.length > 0 }`.
- `elementIcu(node, st, depth)`. Qui `v` è la lettura del valore, e accende sempre `used.arg = true` (`_m` e `_named` stanno nel blocco di `_arg`):
  - chiave numerica (`/^\d+$/`) → `` `${ARG}(a, ${Number(node.value)})` ``;
  - chiave con nome → `` `_key(a, ${JSON.stringify(node.value)})` `` e in più `used.key = true`.

  Poi, secondo il tipo:
  - `argument` → `v`;
  - `number` → `` `_icuN(${v}, ${st.L}, ${optRef(node.vtOptions, st)})` `` e `used.icu.add("icuNumber")`;
  - `date` e `time` → `` `_icuD(${v}, ${st.L}, ${optRef(node.vtOptions, st)}, o)` `` e `used.icu.add("icuDate")`;
  - `select` → `` `_icuS(${v}, { ${rami} })` `` e `used.icu.add("icuSelect")`, dove ogni ramo è
    `` `${JSON.stringify(k)}: () => ${messageExpr(b.value, st, null, depth).expr}` ``;
  - `plural` → `used.icu.add("icuPlural")` e `h = "h" + depth`. Ogni ramo è `` `(${h}) => ${messageExpr(b.value, st, h, depth + 1).expr}` ``.
    Le chiavi `=n` vanno in `exact` con la chiave `k.slice(1)`, le altre in `cats`. Poi:
    `` `_icuP(${v}, ${st.L}, ${node.pluralType === "ordinal" ? 1 : 0}, ${node.offset ?? 0}, ${exact.length ? `{ ${exact.join(", ")} }` : "null"}, { ${cats.join(", ")} })` ``.
- `optRef(opts, st)`: `undefined` → `"void 0"`. Altrimenti `json = JSON.stringify(opts)`: se `used.icuOpts.has(json)` restituisci il
  nome che c'è già; se no `name = "_o" + used.icuOpts.size`, `used.icuOpts.set(json, name)`, e restituisci `name`.

### 1.9 `lib/icu/devInterpret.js` — l'interprete di sviluppo

Serve alla sola finestra "stringa scritta in questa sessione di `vite dev`, non ancora sincronizzata". La tabella non la conosce,
e oggi `resolveEntry.missing()` mostra il fallback del marcatore con `basicHtmlToNodes`. Senza l'interprete, un messaggio ICU
apparirebbe con la sintassi grezza fino al riavvio.

```js
import { parseIcu, TYPE } from "./parse.js";
import { icuNumber, icuDate, icuPlural, icuSelect } from "./runtime.js";
import { argAt, argNamed } from "../namedArgs.js";

/**
 * Riduce un messaggio ICU a testo con "%s" + valori, da passare a basicHtmlToNodes. I valori
 * formattati e quelli grezzi viaggiano come argomenti, così un elemento React resta un elemento.
 * @returns {{ text: string, values: any[] } | null} null se il testo non è ICU o non è valido
 */
export function interpretIcu(text, args, locale, icu) {
  const parsed = parseIcu(text, locale);
  if (!parsed.icu || !parsed.ok) return null;
  // Stessa lettura degli helper compilati (_arg / _key), da lib/namedArgs.js: assente → undefined.
  const valueOf = (key) => (/^\d+$/.test(key) ? argAt(args, Number(key)) : argNamed(args, key));
  const out = { text: "", values: [] };
  const put = (v) => { out.text += "%s"; out.values.push(v); };
  // `h` è il numero già formattato del plurale più interno: prende il posto di "#".
  const walk = (nodes, h) => {
    for (const node of nodes) {
      const v = node.type >= 1 && node.type <= 6 ? valueOf(node.value) : undefined;
      if (node.type === TYPE.literal) {
        out.text += node.value;
      } else if (node.type === TYPE.pound) {
        if (h === undefined) out.text += "#";
        else put(h);
      } else if (node.type === TYPE.argument) {
        put(v);
      } else if (node.type === TYPE.number) {
        put(icuNumber(v, locale, node.vtOptions));
      } else if (node.type === TYPE.date || node.type === TYPE.time) {
        put(icuDate(v, locale, node.vtOptions, icu));
      } else if (node.type === TYPE.select) {
        const fns = {};
        for (const [k, b] of Object.entries(node.options)) fns[k] = () => walk(b.value, undefined);
        icuSelect(v, fns);
      } else if (node.type === TYPE.plural) {
        const exact = {};
        const cats = {};
        for (const [k, b] of Object.entries(node.options)) {
          const fn = (hh) => walk(b.value, hh);
          if (k.startsWith("=")) exact[k.slice(1)] = fn;
          else cats[k] = fn;
        }
        icuPlural(v, locale, node.pluralType === "ordinal", node.offset ?? 0, exact, cats);
      }
    }
  };
  walk(parsed.ast, undefined);
  return out;
}
```

Gli helper di `runtime.js` chiamano i rami e restituiscono ciò che il ramo restituisce: qui `undefined`, perché `walk`
scrive in `out`, e va bene così. Un valore mancante arriva agli helper come `undefined` e torna indietro invariato:
`basicHtmlToNodes` lo mostra come `⁇`, esattamente come fa il percorso compilato con `_arg`.

**a) `test/measureReactBundle.mjs`**: la default export `measureReactBundle` **resta com'è** (la usa `reactBundleSize.test.mjs`

```js
// Gli helper ICU (lib/icu/runtime.js) arrivano all'app in un chunk a parte, e solo se una tabella
// usa l'ICU. Si misurano tutti e quattro, con i rami di sviluppo, come il runtime React qui
// sopra: è lo stesso criterio "al massimo".
export async function measureIcuRuntime() {
  const bundle = await rolldown({ input: join(ROOT, "lib/icu/runtime.js") });
  const { output } = await bundle.generate({ format: "esm", minify: true });
  await bundle.close();
  const chunks = output.filter((o) => o.type === "chunk");
  if (chunks.length !== 1) {
    throw new Error(`expected exactly one chunk, got ${chunks.length}`);
  }
  const code = chunks[0].code;
  return { raw: Buffer.byteLength(code, "utf8"), gzip: gzipSync(Buffer.from(code, "utf8")).length };
}

/** Il peso reale del runtime che un'app può ricevere: React + helper ICU, in byte gzip. */
export async function measureRuntime() {
  const react = await measureReactBundle();
  const icu = await measureIcuRuntime();
  return { react, icu, gzip: react.gzip + icu.gzip };
}

// Come si scrive il peso nei documenti (regola dell'utente, piano 4.6.3): il peso reale si
// arrotonda per difetto al kB (5,4 kB -> "5 kB"); nei confronti vale il kB superiore con "<"
// (5,4 kB -> "<6 kB"; 5,0 kB esatti -> "<6 kB", perché "<5 kB" sarebbe falso). kB = 1024 B.
export function sizeLabels(gzip) {
  const kB = Math.floor(gzip / 1024);
  return { real: `${kB} kB`, compare: `<${kB + 1} kB` };
}

// Ciò che README.md deve contenere per dire il vero (vedi il piano 4.6.3, Fase 5 § 2b). `rounded`
// cambia solo quando si passa un kB; `exact` a ogni release. `forbidden` trova le formule vecchie.
export function expectedReadme(gzip) {
  const { real, compare } = sizeLabels(gzip);
  return {
    rounded: [
      `runtime-${encodeURIComponent(real)}%20gzip-4c1`,
      `weighs ${real} gzip`,
      `Tiny runtime (${compare} gzip)`,
    ],
    exact: `\`${gzip} bytes\``,
    forbidden: /\b(?:under|less than|below)\s+\d+\s*kB|≤\s*\d+\s*kB|%3C%20\d/i,
  };
}
```
