# viteTranslate — minimal demo · Vite 8 + React 19 (JS/JSX only)

The smallest setup that shows the library at work: no TypeScript, ESLint 10 in flat config,
three languages (`it-IT` source, `en-US`, `zh-CN`) and just two code files —
[`src/main.jsx`](src/main.jsx) mounts `<TranslateContainer>`, [`src/App.jsx`](src/App.jsx)
translates the text and switches language with `useTranslateLanguage()`.

The text to translate lives **in the source**, marked with `_%_..._%_`: no keys to invent.
The tables in [`locale/`](locale) are generated by the sync command, reading the
markers from the code.

## Usage

```bash
npm install
npm run dev      # dev server
npm run build    # production build (Rolldown)
npm run preview  # preview the build
npm run lint     # ESLint
```

The dev server doesn't update the tables — the `vtranslate-cli` command does, exposed here as
`npm run prebuild` and already hooked into `npm run build` through npm's lifecycle. So after
adding or changing a marked string in the source, `npm run prebuild` (or `npm run build`
directly) is the step that brings the change into `locale/`. In dev, saving a language
file reloads the page, so a translation you just wrote shows up right away.
